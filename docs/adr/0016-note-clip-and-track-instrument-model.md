# ADR-0016: ノートはクリップに統合し、音色（楽器）はトラック単位で参照する

- ステータス: 採用
- 日付: 2026-11-22
- 決定者: ユーザー（2026-11-22 に推奨案の採用を決定）。提案者: エージェント（Issue #67 の設計提案）
- 採用の理由: ノートをクリップに統合すると、移動・トリム・分割・複製・Undo（History）・MCP 公開といった既存のクリップ操作機構がそのままノートクリップにも効き、コマンド層が唯一の変更経路（ADR-0004）のまま保てる。音色のトラック単位参照は DAW の通例（トラック＝楽器）と一致し、既存サンプラー（Issue #19）の「素材1つを鳴らす」形とそのまま合う。
- 関連: ADR-0004（コマンド層）、ADR-0006（設計判断は人間が持つ）、ADR-0009（ピッチシフトは Signalsmith Stretch）

## 背景

DAW で波形（オーディオクリップ）だけでなく「メロディー（ノート列）」と「音色（楽器）」を分離して管理したい（EPIC #66）。現行モデルにはノートと楽器の表現が無い。

- `Clip`（`crates/studio-core/src/model.rs`）は `source` 参照の波形再生が前提で、ノートの置き場が無い。
- サンプラー楽器（Issue #19、`apps/daw/src/sampler.rs`）はキーボードのライブ演奏専用の note on/off 状態機械で、プロジェクトのタイムライン上のデータとは接続されていない。
- `render_mix`（`apps/daw/src/audio.rs`）は波形クリップしかレンダリング対象にしない。

決めることが4つあった。(1) ノートをモデルのどこに持つか。(2) 音色（楽器）をどの単位で参照するか。(3) 音高の表現。(4) 既存のクリップ操作（分割・トリム等）とノートの関係。

## 決定の内容

### ノートの表現：クリップに統合する

- `Clip` に `notes: Vec<Note>` を追加する（`#[serde(default)]` で旧形式 JSON と互換。波形クリップでは空）。
- `Note` は値データとして次のフィールドを持つ。ノートは独立した ID を持たず、コマンドからはクリップ内の位置（インデックス）で指す（後述）。
  - `pitch: u8`（MIDI ノート番号 0–127、絶対音高）
  - `start_ms: i64`（クリップ相対の開始位置、0 以上）
  - `duration_ms: i64`（長さ、正）
  - `velocity: u8`（0–127）
- **ノートクリップの判定**: `notes` が空でないクリップはノートクリップとして扱い、再生では `source` の波形を鳴らさない。ノートクリップの `source` は空文字で運用する（`AddClip` に空の `source` を渡して作り、ノートを足す）。型で波形／ノートを区別する案は、既存の全クリップ操作を二重化するため採らない。将来、型で区別する必要が生じたら本 ADR を supersede する。
- ノートは常にクリップの範囲内に収まることを不変条件とする（`0 <= start_ms`、`0 < duration_ms`、`start_ms + duration_ms <= clip.duration_ms`）。コマンドはこの条件を検証し、満たさない変更は状態を変えずにエラーにする。

### 音色（楽器）の表現：トラック単位で参照する

- `Track` に `instrument: Option<Instrument>` を追加する（`#[serde(default)]` で旧形式 JSON と互換。None は楽器なし）。
- `Instrument` は enum とし、当面は次の1バリアントのみとする。serde は既存コマンドと同じ `type` タグ形式（`{"type": "sampler", ...}`）。
  - `Sampler { source: String, root_note: u8 }`：`source` の素材を1つ鳴らすサンプラー。`root_note` は素材の原音の音高（MIDI ノート番号）。
- Vital 等の外部プラグインは、後続（Issue #71 の方式決定後、#72）で `Plugin { .. }` バリアントとして足す拡張点とする。本 ADR ではバリアントの詳細は決めない。
- 楽器は **Track に直接持つ**。Project 側の名前付きコレクション＋ID 参照にはしない。名前付きプリセット集が必要になったら、音色管理（Issue #73）で Project 側に足す（Track 直接の形とは両立する）。

### 音高の表現と再生シフト

- 音高は MIDI ノート番号（絶対）で持つ。MIDI 取り込み（Issue #70）が無変換で載り、ピアノロールの音名表示とも合う。
- サンプラー再生時のピッチシフト量は `note.pitch - instrument.root_note`（半音）として導出し、既存の `pitch_shift`（ADR-0009、Signalsmith Stretch）で発音する。

### コマンド

状態変更はコマンド層経由のみ（ADR-0004）。追加するコマンドと担当 PBI は次のとおり。いずれも MCP に公開する。

| コマンド | 内容 | 担当 |
|---|---|---|
| `SetTrackInstrument { track_id, instrument: Option<Instrument> }` | トラックの楽器を設定／解除する | #68 |
| `AddNote { clip_id, pitch, start_ms, duration_ms, velocity }` | クリップにノートを1つ追加する。検証：pitch・velocity は 0–127、ノートがクリップ範囲内に収まること | #68 |
| `MoveNote { clip_id, note_index, new_pitch, new_start_ms }` | ノートの音高と開始位置を変える。検証は AddNote と同じ範囲条件 | #69 |
| `RemoveNote { clip_id, note_index }` | ノートを1つ削除する | #69 |

- ノートの指定はクリップ内のインデックス（`notes` の並び順）で行う。ノートはクリップに従属する値データであり、独立した寿命を持たないため、ID の採番はしない。削除で後続のインデックスがずれるのは、単一コマンドの適用内では問題にならない（GUI はヒットテストで得たインデックスをそのコマンドにだけ使う）。

### 既存のクリップ操作とノートの関係

- **MoveClip / 複製 / Undo**: ノートはクリップ相対なので、そのまま付いていく。追加の扱いは不要。
- **SplitClip**: 分割点（クリップ相対 `rel = at_ms - clip.start_ms`）でノートを振り分ける。
  - 終端が `rel` 以下のノートは左クリップに残る。
  - 開始が `rel` 以上のノートは右クリップへ移り、`start_ms -= rel`。
  - **境界を跨ぐノートは分割点で切る**：左側は `duration_ms = rel - start_ms` に縮み、右側には `start_ms = 0`・残りの長さのノート（同じ pitch・velocity）が生じる。これにより分割前後で鳴るメロディーが変わらない。
  - 右クリップの他の属性の引き継ぎ（フェードインなし、トランジションなし等）は既存の分割規則どおりで、ノートだけが上記に従う。
- **TrimClip**: ノートはクリップに固定される（クリップ相対の位置を保つ）。新しい長さの範囲外に出たノートは削除し、終端がはみ出すノートは収まるよう `duration_ms` をクランプする（フェードやトランジションを新しい長さへクランプする既存の規則と揃える）。開始位置の変更でノートをタイムライン基準にずらすことはしない（波形クリップで TrimClip が `offset_ms` を進めない既存の意味論と揃える）。

### 再生経路の前提（Issue #68）

- `render_mix` がノートクリップを舐め、トラックの `instrument` でノートごとに発音して加算する。発音は既存サンプラーの Voice 機構と `pitch_shift` を再利用し、レンダリングは純粋関数として保つ（ライブ演奏の状態機械とは分離する）。
- ベロシティは 0–127 を 0.0–1.0 のゲインに線形変換する。
- ミュート／ソロ（Issue #39）の効き方は波形クリップと同じトラック単位の規則に従う。楽器が無い（None）トラックのノートクリップは鳴らさない。

## 細部の決定（エージェントの実装レベル判断）

ドラフト（Issue #67）に推奨の明示が無かった細部は、実装レベルの小判断としてエージェントが次のとおり決め、本 ADR に記録する。

- SplitClip で境界を跨ぐノートは「分割点で切る」（鳴るメロディーを保存するため）。
- TrimClip で範囲外になったノートは「削除＋はみ出しはクランプ」（既存のフェード／トランジションのクランプ規則との一貫性）。
- ノートの指定は ID でなくクリップ内のインデックス（ノートに従属データとしての単純さを取り、採番と参照整合の管理を持ち込まない）。
- ノートクリップの `source` は空文字で運用し、ノートクリップかどうかは `notes` の有無で判定する。

## 検討した選択肢

| 論点 | 選択肢 | 長所 | 短所 |
|---|---|---|---|
| ノートの置き場所 | **クリップに統合（採用）** | 移動・トリム・分割・複製・Undo・MCP 公開の既存機構がそのまま効く。コマンド層一元化（ADR-0004）を保てる | 波形とノートで `Clip` の意味が2つになる（`source` を使わないクリップが生じる） |
| ノートの置き場所 | 別エンティティ `MelodyClip` を Clip と並立 | 型で区別が明確 | モデルが2系統になり、移動・複製・分割・Undo・MCP 公開を全部二重に持つ。不整合リスクと実装量が大きい |
| ノートの置き場所 | トラックに直接ノート列を持つ | 単純 | クリップ操作（配置・移動・複製）の再利用ができず、波形クリップと操作体験が揃わない |
| 音色の参照単位 | **トラック（採用）** | DAW の通例と一致。現サンプラーの形と合う。ミックス側の分岐がトラック単位で素直 | クリップごとに音色を変える表現はできない（必要なら後付けの上書きとして拡張可能） |
| 音色の参照単位 | クリップ単位 | 途中で音色を変えられる | UI とミックスが複雑化する。まずトラック単位で出す方が段階的 |
| 音色の参照単位 | ノート単位 | 最も細かい | 過剰。却下 |
| 音高の表現 | **MIDI ノート番号・絶対（採用）** | MIDI 取り込みが無変換。音名表示と合う | サンプラー内部のルート相対表現とは変換（引き算）が要る |
| 音高の表現 | ルート相対の半音数 | 現サンプラーの内部表現と一致 | 楽器を差し替えると同じノート列の意味（絶対音高）が変わってしまい、分離管理の目的に反する |

## 結果

- 後続 PBI は本 ADR の前提で着手できる。#68 はモデル（`Note`／`Clip.notes`／`Instrument`／`Track.instrument`）と `SetTrackInstrument`／`AddNote` を実装し、再生経路を通す。#69 は `MoveNote`／`RemoveNote` とピアノロール UI を実装する。#70 は本 ADR の音高表現（MIDI ノート番号・絶対）の上に SMF 変換を載せる。
- 制約：音色はトラック単位のみ（クリップ単位の上書きは将来の拡張）。ノートクリップと波形クリップは1つのクリップに同居しない（ノートがあればノートクリップとして鳴る）。
- 覆す条件：クリップ単位の音色指定が必須の使い方（1トラック内で音色を切り替える曲作り）が具体化したら、クリップ側の上書きを別 ADR で追加する。ノートに ID が必要になる操作（複数選択やノート単位のリンク等）を実装するときは、ノートの同一性の持ち方を見直す。
