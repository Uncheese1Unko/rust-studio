# ADR-0020: Lua 基盤とスクリプトカタログは共有クレート `studio-scripts` に置く

- ステータス: 採用
- 日付: 2026-11-24
- 決定者: エージェント（実装レベルの判断。#82 レビュー round 1 の Major 指摘への対応として実施し、round 2 で本 ADR の不在が指摘されたため、判断を行った変更とあわせて記録する）
- 関連: ADR-0004（AI ネイティブなコマンド層）、ADR-0008（HTTP API の薄いラッパー方針）、ADR-0019（AviUtl Lua 互換の範囲）、Issue #80／#81／#82

## 背景

Lua 実行基盤（#80）とフレームエフェクト適用（#81）は video-editor の
アプリ内モジュール（`apps/video-editor/src/script.rs`）として作られた。
#82（スクリプトのインストールと管理）で「一覧が GUI と状態ダンプ／
MCP の両方で観測できる」ことが受け入れ条件になり、MCP サーバー
（別プロセス・別バイナリ）からも同じカタログ（走査・構文状態・
有効／無効・プロジェクト参照の欠落）を見せる必要が生じた。

初版の #82 は、MCP 側に名前＋有効／無効だけを返す簡易な走査を
複製した。独立レビュー round 1 はこれを Major とした: 壊れた
スクリプトと欠落参照が MCP で観測できず、走査ロジックの複製は
architecture ルール（ラッパーにビジネスロジックを書かない）にも
反し、拡張子や無効リストの規約が変われば経路ごとにずれる。

video-editor はバイナリクレートであり、studio-mcp からは参照
できない。単一実装を共有するにはクレート化が前提になる。

## 決定

**Lua 実行基盤とスクリプトカタログを共有クレート
`crates/studio-scripts` に置く。** 構成は `engine`（サンドボックス
付き Lua 実行基盤、旧 script.rs）と `catalog`（フォルダ走査・
一覧・有効／無効・参照状態・観測ダンプ、旧 extensions.rs）の
2モジュールとし、video-editor と studio-mcp の双方が依存する。

あわせて、プロセスをまたぐ規約は同クレートの単一の定義に寄せる:

- スクリプト参照の解決規則（`resolve_script_in`）は catalog が持ち、
  アプリ側 media は再公開する。
- 既定のスクリプトフォルダのパス規約（`default_scripts_dir`）は
  catalog が持ち、アプリの `media::scripts_dir` と MCP の既定値の
  双方が委ねる（#82 レビュー round 2 指摘への対応）。

## 検討した選択肢

- **アプリ内モジュールのまま MCP に複製**（初版 #82）: 工数は最小
  だが、観測できる内容が経路でずれ、規約変更で静かに乖離する。
  レビューで却下された。
- **studio-core に入れる**: コアは GUI・メディア・ネットワークに
  依存しない層であり、Lua ランタイム（mlua）とフォルダ走査は
  その責務ではない。却下。
- **MCP がアプリのダンプファイルを読みに行く**: プロセス間の
  ファイル受け渡しは鮮度と競合の問題を持ち、読み取り専用ツール
  のために新しい調整面が増える。却下。

## 結果

- 楽になること: 一覧の形（名前・有効／無効・構文状態・参照状態）が
  GUI ダンプと MCP で構造的に一致する。#83 の AviUtl 互換層も、
  カタログ（拡張子の追加と構文検証の分岐）は同クレートを拡張する
  形で足せる。
- 制約: クレートが1つ増え、video-editor の内部モジュールだった
  ものが公開 API になる。スクリプトフォルダのパス規約は同クレート
  の定義が正となり、アプリのメディア作業フォルダの置き場所を
  変える場合は同クレートも含めて見直す。
- 覆す条件: DAW 側にもスクリプト拡張が広がり、カタログの前提
  （単一フォルダ・名前参照）が合わなくなった場合は、フォルダ
  規約の持ち方を再設計する。
