# ADR-0002: Rust + nannou で作る

- ステータス: 採用
- 日付: 2026-11-21
- 決定者: ユーザー（Rust で、C++ の OpenFrameworks にあたるフレームワークを使う指定）

## 背景

動画編集ソフトと DAW の2本を、同じ技術基盤で作りたい。ユーザーは
C++ における OpenFrameworks のようなクリエイティブコーディング用
フレームワークを Rust で使うよう指定した。Rust のそれは nannou である。
ユーザー自身、Rust/nannou と OpenFrameworks の双方に制作経験がある。

## 決定

言語は Rust、GUI／描画フレームワークは nannou とし、アプリ2本とも
それで作る。実務的なウィジェットが必要な箇所では nannou の egui 統合を
使う余地を残す。

## 検討した選択肢

| 選択肢 | 長所 | 短所 |
|---|---|---|
| Rust + nannou（採用） | ユーザーの指定。描画と音の実験に強い。単一言語で2本を貫ける | DAW/動画編集のような実務 UI の部品は自前になりがち |
| Rust + egui 単体 | 実務 UI が速い | ユーザーの指定（OpenFrameworks 的フレームワーク）から外れる |
| C++ + OpenFrameworks | 本家 | 言語が Rust でなくなる |

## 結果

- nannou のビルドと最小ウィンドウが開発環境で動くことは未検証のため、
  M1 の最初の調査 PBI で証拠付きで確認する（issue-authoring のルール）。
- 実務 UI の負荷が想定を超えた場合、egui 統合の範囲拡大を別 ADR で判断する。
