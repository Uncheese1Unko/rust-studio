# ADR-0023: トラックエフェクトは「パラメータはコア、DSP はアプリ側」のチェーンとして持つ

- ステータス: 採用
- 日付: 2026-11-25
- 決定者: エージェント（EPIC #91 の実装レベルの判断。対象3種と「再生と書き出しの両方に効く」「コマンド層に乗せる」はユーザーの指定範囲内）
- 関連: ADR-0004（コマンド層が単一の変更経路）、ADR-0005（状態ダンプは画面で観測できるものと一致する）、ADR-0014（フェード／トランジションはクリップの属性として持つ）、アーキテクチャルール（重いメディア処理はコアに入れない）

## 背景

DAW にはトラック単位のエフェクトが無く、音量・パン以外で音を加工できない（EPIC #91）。エフェクトを足すにあたり、次の制約がある。

- 状態の変更はコマンド経由のみ（ADR-0004）。追加・削除・並べ替え・パラメータ変更・バイパスがコマンドで表せ、失敗時に状態不変で、Undo が効くこと。
- 状態ダンプにチェーンがそのまま現れること（ADR-0005）。
- 信号処理（DSP）はコアに入れない（アーキテクチャルール）。コアはパラメータだけを持つ。
- 既存プロジェクト JSON がそのまま読み込めること（serde default）。
- 既定（チェーン空）では従来と音が変わらないこと。

## 決定

**`Track.effects: Vec<EffectSlot>` としてチェーンを持ち、`EffectSlot { effect: TrackEffect, bypassed }`、`TrackEffect` は `Reverb { decay, mix }` / `Delay { time_ms, feedback, mix }` / `Eq3 { low_gain_db, mid_gain_db, high_gain_db }` の enum とする。**

- パラメータ範囲はコマンド層が検証する: Reverb は decay・mix とも 0.0..=1.0、Delay は time_ms 1..=2000・feedback 0.0..=0.9・mix 0.0..=1.0、Eq3 は各ゲイン -24.0..=24.0 dB。非有限値は弾く。
- コマンドは5種: `AddTrackEffect`（戻り値はスロット位置）、`RemoveTrackEffect`、`MoveTrackEffect`、`SetTrackEffect`（スロット全体の差し替え。バイパスは保たれる）、`SetTrackEffectBypass`。スロットは ID を持たず位置（インデックス）で指す（クリップ内ノートと同じ扱い、ADR-0016）。
- DSP は DAW アプリ側 `apps/daw/src/effects.rs` に置き、依存クレートは足さない。EQ は RBJ Cookbook のアナログ原型（ローシェルフ 200Hz／ピーキング 1kHz Q=1／ハイシェルフ 4kHz、棚の Q は S=1 相当）を双一次変換した biquad。係数は導出過程で DC・中心・Nyquist のゲインで検算した（当初、暗記した Cookbook の閉形式で書いたところ極が単位円外に出て不安定になったため、原型からの導出に切り替えた。経緯は試験レポート issue-0092）。
- 適用位置: `render_mix` はトラックごとにドライ信号をバッファへ描き、チェーンを通してから、トラック音量・パンを掛けて合算する（音量・パンはポストフェーダー）。DSP の状態はレンダリング呼び出しごとに生成し、`render_mix` の純粋性（同じ入力→同じ出力）を保つ。
- ディレイ／リバーブの DSP は Issue #93、GUI 編集は #94、MCP／API の受け入れ確認は #95 で扱う（本 ADR は表現と適用方式まで）。

## 検討した選択肢

| 選択肢 | 長所 | 短所 |
|---|---|---|
| **スロット列＋enum（採用）** | 順序とバイパスが状態にそのまま現れる。種類の追加はバリアント追加で受けられる（ADR-0016 の楽器と同じ拡張点）。コマンドが素直 | スロットに ID が無いため、並べ替えを跨いだ参照はできない（GUI の選択状態は位置で持ち、トラック切り替え時に戻す運用で足りる） |
| 種類ごとに固定スロット（reverb/delay/eq の各フィールド） | 単純 | 順序変更が表現できない。同種を2つ掛けられない。フィールドが増えるたびにモデルが変わる |
| クリップ属性として持つ（フェード等の前例） | 既存パターンに一致 | ユーザーの指定はトラック単位。クリップ分割のたびに引き継ぎ規則が要り、トラック全体への一括調整ができない |
| DSP までコアに置く | render の所在と一致させやすい | アーキテクチャルール（重い処理はコアに入れない）違反。video-editor と共有するコアに DAW 固有の信号処理が入る |

## 結果

- エフェクトの追加・変更が全経路（GUI／MCP／HTTP API）で同じコマンドに乗り、ダンプで観測でき、Undo が効く。
- 制約: パラメータは固定帯域・固定形のみ（EQ の周波数や Q は変えられない。必要になったらパラメータ追加で受ける）。DSP 状態はレンダリングごとに初期化されるため、書き出しと再生で区切り位置が違えばリバーブ等の残響の継ぎ目が原理上ありうる（現行の render_mix 全体が同じ前提）。
- 覆す条件: プラグイン形式のエフェクト（VST/CLAP の汎用ホスティング）を扱う判断が別途なされたら、チェーンの表現を再検討する。
