# ADR-0018: 音色は Project の名前付きコレクションとして持ち、トラックは参照する

- ステータス: 採用
- 日付: 2026-11-22
- 決定者: エージェント（Issue #73 の実装方針としてイシュー本文が第一候補として提示した方式の範囲内。ADR-0016 の「トラック直接」モデルへの拡張であり、ユーザーの設計判断が必要な論点は含まない）
- 関連: ADR-0016（楽器はトラック単位。本 ADR はその上に名前付きコレクションを足す）、ADR-0017（Vital はヘッドレス。音色管理はプリセット参照の切り替えまでで、パラメータ編集は行わない）

## 背景

Issue #73: 音色を作成し、名前を付けてプロジェクトに保存し、トラックへ
割り当てて切り替えたい。ADR-0016 の時点では楽器はトラックに直接持つ
形（`Track.instrument`）で、同じ音色を複数トラックで再利用したり、
名前で管理したりする仕組みが無い。イシュー本文は「音色は Project 側の
名前付きコレクションとして持ち、トラックはそれを参照する形」を第一候補
として提示していた。

## 決定

**`Project.tones: Vec<Tone>` を追加し、`Tone { id, name, instrument }` とする。
トラックは `Track.tone_id: Option<u64>` で参照する。**

- 実効楽器は `Project::effective_instrument(track)` で解決する
  （音色が割り当てられていれば音色の楽器、無ければトラック直接の楽器）。
  再生（render_mix）・プラグイン事前レンダリング・指紋はすべて実効楽器で見る。
- 音色の追加・改名・中身の差し替え・削除・割り当てはコマンド化する
  （AddTone / RenameTone / UpdateTone / RemoveTone / SetTrackTone）。
  中身の差し替えは参照経由で割り当て中の全トラックに即座に反映される。
- 音色を削除すると、参照していたトラックの tone_id は外れる
  （直接の楽器設定に戻る。黙って無音にしない）。
- トラックへ直接楽器を設定（SetTrackInstrument）すると tone_id は外れる
  （直接設定と参照の二重管理を避け、直接設定を優先する）。
- Vital プリセットのパラメータ編集（.vital の JSON 書き換え）はしない
  （ADR-0017 で GUI 編集は対象外。音色としての管理はプリセットファイル
  への参照の切り替えまで）。
- 旧形式のプロジェクト JSON との互換は `#[serde(default)]`
  （tones は空、tone_id は None）で保つ。

## 理由

- 音色の実体を1か所に持つため、同じ音色の使い回しと一括変更ができる
  （コピーを各トラックに持つ方式では中身の同期が取れない）。
- 既存のクリップ操作・Undo・MCP の枠組みにそのまま乗る
  （ADR-0016 で楽器をトラック参照にした判断と同じ理由）。
- 削除・直接設定時の参照の扱いをコマンド層で一元化でき、状態の
  不整合（参照先が無いのに鳴らない等）を型と検証で防げる。
