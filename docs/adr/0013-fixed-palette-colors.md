# ADR-0013: トラック／クリップの色付けはテーマ固定パレット方式とする

- ステータス: 採用
- 日付: 2026-11-22
- 決定者: ユーザー
- 関連: ADR-0012（DAW のビジュアルテーマ）、イシュー #58・#59

## 背景

ユーザーが実機で両アプリを触り、「一般的な機能以前の問題」として、
トラック（レイヤー）を追加できない・ファイルをドロップで取り込めない・
色を付けられない、と指摘した。色については、モデル
（`crates/studio-core/src/model.rs`）に色を保持する項目自体がなく、
クリップ色はトラック種別で固定されている（DAW は
`apps/daw/src/timeline.rs` の `clip_colors`）。色付け PBI（#58・#59）は
「色の指定方式」「状態色との衝突」「データの持ち方」の3点が
needs-decision として残っていた。

## 決定

色付けは**テーマに合う固定パレットから選ぶ方式**とする。任意の RGB を
指定する自由色は採らない。

- パレットの色はテーマの色体系（ADR-0012、DAW は
  `docs/design/daw-visual-design.md` の配色表）から決める。
- **パレットに ACCENT（ホットピンク `#FF2E88`）そのものは含めない。**
  ACCENT は「再生中」の専用色であり、ユーザー色に混ざると判読できない。
  淡色側（ACCENT_SOFT 等）は候補にしてよい。
- **再生中のクリップは、色設定の有無・内容にかかわらず ACCENT で
  上書きして描く**描画順序を必須とする。状態色の意味はユーザー色より
  優先する。
- データは**パレット識別子**（名前）でモデルに保持する。未設定は
  「なし（既定の種別色）」を意味し、旧形式 JSON との互換のため
  serde の既定値で読み込む（Track.volume / pan、Clip.cutout /
  pitch_semitones の追加時の前例どおり）。

## 検討した選択肢

| 選択肢 | 長所 | 短所 |
|---|---|---|
| テーマ固定パレットから選ぶ（採用） | ADR-0012 のテーマと常に調和する。状態色との衝突を設計側で排除できる。選択 UI が小さい | 選べる色の自由度はパレットの範囲に限られる |
| 任意の RGB を自由に指定する | 自由度が最大 | テーマとの調和と状態表示の判読性を壊しやすい。色選択 UI の実装量が大きい。ACCENT と同色を選べてしまう |

## 結果

- #58（DAW の色付け）と #59（動画編集の色付け）は本 ADR を前提に
  着手できる。パレットの具体的な色並びは各 PBI の実装時にテーマの
  色体系から決め、試験レポートに記録する。
- 動画編集には ADR-0012 のテーマが未適用だが、色の保持方式
  （パレット識別子・未設定＝種別色・serde 既定）は両アプリ共通とする。
  動画編集側のパレット色値は #59 で決める。
- 覆す条件：ユーザーが自由色を求めた場合。そのときは新 ADR で
  supersede する。
