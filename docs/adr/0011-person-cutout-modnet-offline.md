# ADR-0011: 人物切り抜きは MODNet をワーカースレッドでオフライン処理する

- ステータス: 採用
- 日付: 2026-11-21
- 決定者: エージェント（実装レベルの判断として記録。ADR-0006 の範囲内。ユーザーの差し替えはいつでも可能）
- 関連: Issue #21（調査）, Issue #22（実装）, ADR-0004（コマンド層が単一の変更経路）

## 背景

Issue #21 の調査で、実行可能な品質・ライセンス・サイズの観点から
MODNet（ONNX、Apache-2.0、25.9MB）を第一候補とし、BiRefNet は
この検証環境（メモリ 6GB）では OOM で品質未検証、RVM は背景の
残像が残る、RMBG-2.0 は非商用ライセンスで除外、という結果だった。
#22 の実装方式（実行基盤・処理形態・合成方法）を決める必要がある。

## 決定

- モデルは **MODNet** とし、推論は `ort` クレート（ONNX Runtime、
  **load-dynamic** 方式）で行う。load-dynamic にすることでビルド時に
  バイナリをダウンロードせず、CI のビルドがネットワークに依存しない。
  実行時は `ORT_DYLIB_PATH` 等で libonnxruntime の場所を解決し、
  見つからなければ切り抜きは「利用不可」として通常プレビューを続ける。
- 処理形態は **オフライン処理**: フレーム列に対してワーカースレッドで
  1枚ずつ推論し、進捗は共有状態（JobState）で GUI に表示する。
  UI スレッドでは推論しない（固まらない）。
- 適用の有無はクリップの状態として持ち、変更はコマンド層経由
  （`SetClipCutout`、ADR-0004）。マスク列と合成済みフレーム列は
  メディア置き場にファイルとして残す。
- 合成先は、同じ時刻を覆う別映像トラックのクリップ（背景クリップ）、
  無ければ単色背景とする。プレビューは合成済みフレームを優先表示する。
- モデルファイルの場所は `STUDIO_MODNET_MODEL`、なければメディア
  置き場の `modnet.onnx`。モデル自体はリポジトリに含めない。

## 検討した選択肢

| 選択肢 | 長所 | 短所 |
|---|---|---|
| MODNet + ort load-dynamic（採用） | #21 で実測済みの品質と速度（512² で約 0.65 秒/枚）。Apache-2.0。ビルドがオフラインで完結 | 実行時に libonnxruntime の配置が要る |
| BiRefNet | 高品質で知られる | fp16 でも 490MB。この環境では OOM で未検証。実機確認が前提になる |
| RVM | 高速（約 0.1 秒/枚） | #21 の実測で背景の残像・誤検出が残った |
| UI スレッドで同期処理 | 実装が単純 | 1枚約 0.65 秒固まり、プレビューが止まる |

## 帰結

- 推論基盤は cutout モジュール内に閉じているため、将来 BiRefNet 等へ
  差し替える場合は同モジュールの差し替えで済む。
- 実人物素材での精度は未検証（検証素材はテストパターンおよび
  #21 のサンプル動画）。実機・実素材での確認は別途必要。
