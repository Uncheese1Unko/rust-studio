## 根本原因

`apps/video-editor/src/main.rs` の `model()` で
`app.set_exit_on_escape(false)` を呼んでおらず、nannou 既定の
「Escape でアプリ終了」が有効なままだった。DAW は #40 で
ループ解除に Escape が必要になった際に同じ設定を入れており、
動画編集側だけが漏れていた。

## 再現（修正前）

Xvfb（:94）でアプリを起動し、描画開始（`elements:` 出力と
スクリーンショットの非黒ピクセル）とプロセス生存を確認したうえで
Escape を1回送信すると、2秒後にプロセスが終了していた。
#63 の GUI ドライブ初回でも、状態リセット用に送った Escape で
アプリが終了し、後続のキー操作が全て無効になった（ドライブ側は
Escape を送らない形に変更して回避。本レポートの修正で不要になる）。

## 修正

`model()` の先頭で `app.set_exit_on_escape(false)` を呼ぶ
（DAW `apps/daw/src/main.rs:317` と同一の形）。Escape は
リネーム編集のキャンセル（#57）で使うキーであり、編集中以外の
Escape で作業中の状態を失うのは誤動作である。

## TDD の記録

- 本変更は nannou の App 設定フラグであり、単体テスト可能な
  振る舞いではない。そのため「再現する落ちるテスト」に代えて、
  修正前の実アプリでの再現（Escape でプロセス終了）を記録し、
  修正後に同じ手順のドライブで生存を確認した。DAW #40 の前例も
  同じ進め方（フラグ自体の単体テストなし、GUI ドライブで検証）。

  `xdotool click --repeat` では速すぎてアプリのフレームポーリングに
  拾われず、`mousedown`/`mouseup` を 0.15s 間隔で2回送る方式にした
  （ダブルクリック判定は 400ms 以内）。
