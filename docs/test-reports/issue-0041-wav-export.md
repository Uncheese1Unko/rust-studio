## 受け入れ条件ごとの結果

### AC1: プロジェクト全長を 44.1kHz/16bit PCM/ステレオで書き出せる — ✅

- `audio::export_wav` が `project_end_ms` までを hound で書き出す
  （WavSpec は 2ch / 44100 / 16bit Int で固定）。
- テスト（イシュー指定名）`exported_wav_round_trips_with_same_samples`
  が decode_audio で読み戻してレート・チャンネル・長さを検証。
  CLI の実測でも 2000ms → 88200 フレームちょうどを確認した。

### AC2: 中身が render_mix の出力と一致し、無音でない — ✅

- 書き出しは render_mix の出力を 16bit 量子化するのみ。同テストが
  読み戻しサンプルと render_mix 出力を量子化誤差（2/32767）以内で
  全数比較し、rms > 0.05 で非無音も検証。ドライブでも peak 13106
  （0.4 振幅のトーンと整合）と、クリップ開始前の無音区間を確認。

### AC3: GUI のボタンから書き出し先を選んで実行でき、完了が画面に表示される — ✅（留保つき）

- EXPORT チップ（トランスポート、ループチップの右隣）を押すと、
  初期値の書き出し先（プロジェクトと同じ場所の
  `<プロジェクト名>.wav`、イシューの実装方針どおり）に書き出し、
  完了をチップに表示する（`EXPORTED <ファイル名>`）。
- **留保**: OS のファイルダイアログで保存先を選ぶ操作は実装して
  いない（ヘッドレス環境で検証できるダイアログ基盤がなく、
  イシューの実装方針も初期値を定めている）。書き出し先の変更は
  CLI の引数では可能。ダイアログ対応は必要なら別途。
- 失敗時は `EXPORT FAILED` と表示し、成功と偽らない
  （レビュアーが書けないパスで実測）。

### AC4: CLI（--export-wav <project.json> <out.wav>）でも書き出せる — ✅

- `export_wav_cli` がプロジェクト JSON を読み、素材をデコード
  して書き出す。ドライブで GUI と同じプロジェクトから書き出し、
  形式・長さ・非無音・先頭無音を検証した。

## 実装中の記録（正直な記録）

- CLI の初回実測で無音になった。原因は検証用フィクスチャが
  参照したデモ素材（/tmp 配下）が消えていたことで、製品コードの
  欠陥ではなかった。ドライブでは素材をその場で生成する形にして
  再現可能にした。なお decode できない素材は compute_audio_map が
  静かに読み飛ばすため、素材欠落時は無音の書き出しになる
  （GUI では起動時にデモ素材を生成し直すため通常起きない）。
- レビュー所見への対応（`3503efa`）: 完了表示のチップには
  ファイル名のみを出す（絶対パスは stdout に残す）。あわせて
  export_wav の挿入で render_mix_with_metronome の doc コメントが
  付け替わっていたのを直した。
