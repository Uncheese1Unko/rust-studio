## 受け入れ条件ごとの結果

### AC1: タイムライン全体を mp4 に書き出しでき、ffprobe で長さ・解像度・コーデックが ADR 仕様どおり — ✅

- 全長は全トラックを通じたクリップ終端の最大値（イシュー指定
  テスト `export_plan_covers_timeline_length`）。既定は ADR の
  1280x720 / 30fps。
- 実地（`evidence/issue-0054/cli-evidence.txt`）: 8000ms の
  プロジェクトで H.264 / 1280x720 / AAC / duration 8.000、
  r_frame_rate 30/1、音声 sample_rate 48000 を確認。

### AC2: 書き出しの中身がタイムラインと一致する（プレビューと同じ規則） — ✅

- フレーム選択は `export_frame_at`（テスト
  `export_frame_at_follows_preview_rules`）: 覆われない時刻は
  黒、素材時刻は offset 込み、トランジション窓は ADR-0014 の
  α ブレンド、優先順位はプレビューと同じ「切り抜き ＞
  ブレンド ＞ 素フレーム」。
- 実地: 赤クリップ→α=0.5 のブレンド（平均 (118.3, 39.4,
  116.4)）→黒（隙間）→赤クリップ、と書き出し mp4 から
  抽出したフレームで確認（証拠にフレーム画像あり）。
- 音声は DAW の render_mix と同じ規則でステレオ 48kHz に
  ミックス（テスト `mix_audio_applies_gain_fade_and_track_
  settings` で数値確認）。#51 の範囲どおり、プレビューに
  音声経路はないため、ゲイン／フェードの音への反映は本件の
  書き出しが担う。

### AC3: GUI のボタンで書き出しでき、進捗と完了が画面に表示される — ✅

- EXPORT MP4 ボタン（ゲインスライダーの下）でバックグラウンド
  書き出しを開始し、進捗「EXPORTING n/total」と完了
  「EXPORTED: <path> (<n> frames)」を画面に表示する。
- 実アプリ証拠（`evidence/issue-0054/`）: ボタンを押して
  180 フレームの書き出しが完了し、ステータス表示と出力
  ファイル（H.264/AAC、6.000 秒）を確認。初回はステータス
  文字色が背景と同化して見えなかったため、明色に直して
  再撮影した。

### AC4: CLI `--export-mp4 <project.json> <out.mp4>` でも書き出しできる — ✅

- 進捗を標準出力へ出し、成否を終了コードで返す。上記 AC1/AC2
  の実地確認はすべて CLI 経由。存在しないディレクトリへの
  書き出しも、ディレクトリをエンコード前に作るため成功する。

## ADR-0015 との差分（記録）

- 切り抜き合成は「書き出し解像度で再構成」ではなく、プレビュー
  が作った合成済みフレーム（320x180）を拡大して使う。合成
  パイプライン自体がプレビュー解像度で動くためで、コード内
  コメントにも明記した。リサイズに失敗した場合は寸法混在を
  避けるため、書き出し解像度の素フレーム／黒で代替する。
- ピッチシフトはミックスに適用しない（ADR-0015 が列挙する
  規則に含まれないため。コード内コメントに明記）。
- 映像ソースに埋め込まれた音声は対象外（ADR の明記どおり）。

## コードレビュー

- 独立 code-reviewer（新規サブエージェント、イシュー番号と diff
  範囲のみを提示）。
- ラウンド1: **CHANGES_REQUESTED**。Major 1件（再書き出し時に
  前回のフレームが作業領域に残って混入し、出力が長くなる）、
  Medium 2件（一時ファイルが書き出し先と別ディレクトリで
  rename が失敗しうる／フレーム列の文字列ソートが 1000 枚超で
  崩れる）、Minor 3件（素材終端超えの無音化、切り抜き優先
  順位、証拠への fps・サンプルレート追記）。すべてテスト
  先行で対応し、Major は実地でも回帰確認した（6000ms →
  2000ms の再書き出しで duration が 6.000 → 2.000）。
- ラウンド2: **CHANGES_REQUESTED**（残件 Minor 1件のみ）:
  切り抜きのリサイズ失敗時にプレビュー解像度のファイルを
  そのまま返す経路が残っていた。レビュー上限（2ラウンド）の
  作法に従い、受け入れ条件範囲内のこの残件を修正してから
  close する（3ラウンド目のレビューは行わない）。あわせて
  範囲外の観察（書き出し先ディレクトリの作成がエンコード
  後段にあった）も同コミットで直した。
