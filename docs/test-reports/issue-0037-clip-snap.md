## 受け入れ条件ごとの結果

### AC1: 移動で開始位置が小節線・他クリップの端・再生ヘッドに 8px 以内で吸着する — ✅

- `edit::snap_target`（純粋関数）が候補（再生ヘッド／他クリップの
  端／小節線）から最寄りを選ぶ。しきい値は画面の 8px を
  `px_per_ms` で ms に換算する（960px 幅では 95ms）。
- 優先順はイシューの方針どおり「再生ヘッド → クリップ端 →
  小節線」で、同距離ではこの順に選ぶ（候補に優先順位を持たせ、
  (距離, 優先順位) の最小を選ぶ）。
- テスト（イシュー指定名）`snap_picks_nearest_bar_line_within_threshold`:
  しきい値内では小節線に吸着、外では元の位置。
  `snap_prefers_playhead_then_clip_edge_on_ties` が同距離の
  優先順を検証。
- 実アプリ証拠: raw では開始 1952ms になるドラッグが、小節線
  2000ms に吸着して保存された（`evidence/issue-0037/`）。

### AC2: トリム（左右端のドラッグ）でも同じ吸着が効く — ✅

- 左トリムは開始端を吸着し、終端が変わらないよう長さを再計算。
  右トリムは終端を吸着する。テスト
  `drag_move_and_trim_snap_through_context` が左トリム
  （再生ヘッド 500 へ吸着・終端不変）と右トリム（他クリップの
  端 5000 へ吸着）を検証。

### AC3: Alt キーを押しながらドラッグすると吸着が無効になる — ✅

- main.rs が LAlt/RAlt を検出して `snapped_command_for` の
  有効フラグを切り替える。無効時は候補がそのまま返る。
- 実アプリ証拠: 吸着後（2000ms）のクリップを Alt を押しながら
  小さく左へドラッグすると、raw の 1952ms に留まり 2000 へ
  戻らなかった。

### AC4: 吸着した結果はコマンド経由で適用され、状態ダンプで観測できる — ✅

- スナップは候補コマンドの生成段のみ。適用は従来どおり
  `History::apply_transient` → ジェスチャ終了時に履歴確定で、
  `after drag:` ダンプに吸着後の位置が記録される（証拠の
  gui-stdout.txt）。

  掴み直すようにして安定させた。
