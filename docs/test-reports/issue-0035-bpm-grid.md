## 受け入れ条件ごとの結果

### AC1: Project に bpm が保持され（既定 120、旧 JSON は既定値）、SetBpm で変更でき、範囲外は失敗して状態不変 — ✅

- `Project.bpm: f32` に `#[serde(default = "default_bpm")]`（120.0）。
- `SetBpm` は有限でない値と 20 未満・300 超を `InvalidRange` で弾き、
  代入前に検証するため失敗時に状態は変わらない。
- テスト: `set_bpm_applies_and_validates_range`（境界 20/300 は成功、
  19.9/300.1/0/負/NaN/∞ はエラー＋ダンプ不変）、
  `legacy_json_without_bpm_loads_default_120`（往復保存も確認）。

### AC2: トランスポート表示に BPM が大きく表示され、GUI から変更できる — ✅

- トランスポート右側に `VALUE_FONT_SIZE` で「120 BPM」形式の大表示。
- クリックで入力モード（`edit::BpmEdit`、数字と小数点のみ、最大6文字）
  に入り、Enter で SetBpm をコマンド経由で確定、Esc で取消。範囲外で
  弾かれた場合はセッションを閉じずに `bpm rejected` を出す
  （リネームと同じ扱い）。
- 実アプリ証拠（`evidence/issue-0035/drive.sh`）: bpm=240 の
  プロジェクトを開き、BPM 表示をクリック→BackSpace で消去→
  「120」を入力→Enter で確定。保存されたプロジェクトの bpm が
  120.0 になり、`after bpm:` ダンプでも観測できた。入力中の
  スクリーンショット（`shot2-editing.png`）ではバッファと下地が
  表示されている。
- 配置の都合で、dB ラベルと時刻ラベルを BPM 表示の右側に少し
  寄せた（重なり回避）。

### AC3: ルーラーに小節番号と小節線が BPM から計算されて表示される（4/4 固定） — ✅

- `timeline.rs` に純粋関数 `beat_duration_ms`（60,000/bpm）、
  `bar_duration_ms`（×4）、`bar_start_ms` を追加。
- テスト（イシュー指定名）: `bar_start_ms_follows_bpm` —
  bpm=120 で小節頭が 0, 2000, 4000, 10000 になることを確認。
- 描画はトラック行とクリップの描画後に重ねる（先に引くと行の地色で
  上塗りされるため。ドライブで検出して直した）。
- ピクセル検証: 1000ms 地点の小節線が bpm=240 では存在し（地色から
  十分離れた色）、bpm=120 では消える（地色に戻る）ことを確認した。
  線は1px幅でアンチエイリアスされるため色の近さではなく地色との
  距離で判定した。

### AC4: MCP から BPM を設定でき、ダンプで観測できる — ✅

- `set_bpm` ツールを公開（コマンドは17種に）。テスト
  `set_bpm_tool_applies_via_tools_call`: 既定120の確認→90 適用→
  ダンプで観測→301 はエラーで状態不変。tools/list の期待リストにも
  追加。

## 既存の仮置き（bar_at_ms / beat_at_ms）の扱い

- #24・#27 時点の「1秒＝1小節／1拍250ms」は、モデルにテンポが
  無かったための仮置きだった。本 PBI で BPM ベースの計算に置き換え、
  旧仮置きは bpm=240 と等価であることを明記したうえで、既存テストの
  期待値は bpm=240 を渡してそのまま維持し、bpm=120 の期待値を追加
  した。呼び出し側（トランスポート表示・BAR チップ）も BPM を
  渡すよう追随した。
