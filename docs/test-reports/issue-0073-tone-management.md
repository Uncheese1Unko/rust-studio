# 試験レポート: Issue #73 音色を作成・保存・切り替えできる（プロジェクト内の音色管理）

## 受け入れ条件と結果

具体化した受け入れ条件（イシューコメントで明記した4件）で検証した。

| # | 条件 | 結果 |
|---|------|------|
| 1 | 音色を作成し（パラメータ変更またはプリセットの取り込み）、名前を付けてプロジェクトに保存できる（GUI／MCP＋ダンプ確認） | ✅ コアテスト（AddTone で dump に tones と名前が現れる）、MCP テスト（add_tone／rename_tone 経由）、GUI 駆動（「+ TONE FROM TRACK」で選択中トラックの楽器から作成→ファイル保存を確認） |
| 2 | 保存した音色が再読込後も残り、一覧から選べる（保存→再読込→一覧） | ✅ プロジェクト JSON 往復テスト（tones＋tone_id が復元される）。GUI では音色パネルにチップとして一覧表示される（スクリーンショット） |
| 3 | トラックへ割り当て・切り替えると再生される音が変わる（render_mix 出力の変化＋実アプリ確認） | ✅ render_mix テスト: root_note 60／48 の音色2つを切り替えると出力が 220Hz→440Hz に変わり、UpdateTone の差し替えも即反映。プラグイン音色も事前レンダリング対象になることをテスト。GUI 駆動で割り当て操作とチップの点灯を確認 |
| 4 | 音色の状態が状態ダンプで観測できる | ✅ dump_json に tones／tone_id が含まれ、MCP の project dump でも同じ状態が観測できる（MCP テスト） |

## 設計

ADR-0018（音色は Project の名前付きコレクションとして持ち、トラックは参照する）。
実効楽器は `Project::effective_instrument` で解決し、再生・プラグイン事前
レンダリング・指紋はすべて実効楽器で見る。Vital プリセットのパラメータ編集
（JSON 書き換え）は ADR-0017 の確定どおり行わず、音色としての管理は
プリセット参照の切り替えまで。
