## 設計

- `timeline::ViewScale { zoom: f32, offset_ms: i64 }` を表示状態の
  単一の出所とした。`px_per_ms`／`time_to_x`／`x_to_ms` は倍率と
  オフセット込みの換算をこの型に寄せ、`layout_clips`／
  `playhead_x`／`edit::x_to_ms`／`edit::hit_test` はスケールを
  引数に取る形へ変えた（イシューの方針どおり）。
- `zoom_at(factor, anchor_ms, anchor_x, width)` がアンカーの画面
  位置を保ったまま倍率を変え、倍率は 0.25..=8 にクランプ、
  オフセットは 0 未満にならない。`scroll_by` も 0 でクランプ。
- nannou 0.19 には Builder の mouse_wheel 登録がなく、ホイールは
  `event()` に `WindowEvent::MouseWheel` として届くため、そこで
  捌く形にした。

## 受け入れ条件ごとの結果

### AC1: Ctrl+ホイールで拡大・縮小でき、クリップ・波形・ルーラーが同じ倍率で描かれる — ✅

- 描画はすべて `model.view_scale` 経由（ルーラーの秒・小節線は
  表示範囲だけを反復、クリップ矩形・波形・フェード傾斜も同倍率）。
- 実アプリ証拠: Ctrl+ホイールで zoom 1.25→2.44 と段階的に上がり、
  x=200 のピクセルが地色からクリップ面（ACCENT）に変わった
  （`evidence/issue-0038/`）。

### AC2: 拡大時に水平スクロールでき、再生ヘッドが画面外でも再生が続く — ✅

- 通常ホイールで offset が 100ms 単位で動き、0 で止まる
  （証拠ログ: 2531→3131）。
- 再生の前進（`advance_playhead`）は表示状態を一切参照しない
  ため、ヘッドが画面外でも再生は進む（コード確認。レビュアーも
  同じ判定）。

### AC3: ズームしてもドラッグ移動・トリムのヒットテストと ms 換算がずれない — ✅

- テスト（イシュー指定名）`x_to_ms_round_trips_at_any_zoom`:
  倍率 0.25/0.5/1/2/8 × オフセットで ms→px→ms がピクセル量子化
  の誤差以内で往復する。`hit_test_uses_view_scale` が zoom2・
  offset1000 で判定が変わることを検証。スナップのしきい値換算も
  スケール経由に直した。

### AC4: 倍率とスクロールはプロジェクトに保存されず、再起動で初期倍率に戻る — ✅

- `view_scale` は Model のフィールドのみで、初期化は
  `ViewScale::default()`（1.0 倍・オフセット 0）。ドライブで
  ズーム＋スクロール後にプロジェクト JSON が元のままである
  ことを assert した。

## GUI ドライブの注記（正直な記録）

- X11 ではホイールボタンの press/release が各1イベントになる
  ため、xdotool の2クリックで4段（1.25^4 ≒ 2.44倍）ズームした。
  アプリ側の挙動は1イベント1段で一貫しており、ドライブの
  期待値を実挙動（4段・アンカー保持・スクロール6イベント×
  100ms）に合わせて検証した。
- レビュアーの非ブロッキング所見: 再生ヘッドの小節チップは
  画面内にクランプされるため、ヘッド本体が画面外でもチップ
  だけ端に残る（見た目の軽微な不整合。受け入れ条件の違反では
  ないため本件では直さない）。
