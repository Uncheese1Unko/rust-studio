## 受け入れ条件ごとの結果

### AC1: ON で拍の位置にクリックが合成され、小節の頭は高い音になる — ✅

- `audio::add_metronome_clicks` が拍（プロジェクト先頭から数える）
  にクリックを合成する。クリックは短いサイン波×指数減衰（30ms、
  振幅 0.5 固定）、強拍（小節頭、4拍ごと）は 2000Hz、弱拍は
  1000Hz（イシューの実装方針どおり）。
- テスト（イシュー指定名）`metronome_clicks_land_on_beats`:
  bpm=120 で 0/500/1000/1500ms の各30ms窓のピーク > 0.3、拍間
  （240–260ms、740–760ms）は < 0.01 の無音を確認。さらに
  Goertzel 解析で 0ms 窓は 2000Hz、500ms 窓は 1000Hz が支配的
  であることまで波形で検証した。

### AC2: トランスポートに ON/OFF トグルがあり、OFF ではクリックが混ざらない — ✅

- トランスポート左下にチップ（OFF は PANEL_SUNK 地に
  「METRONOME OFF」、ON は ACCENT ピンクに「METRONOME ON」）を
  置き、クリックで切り替える。ON/OFF はアプリ側の再生状態
  （`Model.metronome_on`）で、プロジェクトには保存しない。
- テスト `metronome_off_adds_no_clicks`: OFF ではミックスが
  完全に無音（空プロジェクト）。OFF 経路は素の render_mix を
  そのまま返す構造。
- 実アプリ証拠（`evidence/issue-0036/drive.sh`）: チップを
  クリック → stdout に `metronome: on`、チップのピクセルが
  (243,231,217) → (255,46,136) に変わることを確認。
- 再生レンダリングへの組み込み: GUI の update() が使う render
  呼び出し（レベルメーター窓）を `render_mix_with_metronome` に
  差し替えた。本コードベースに実時間の音声デバイス出力はなく、
  render_mix 系が再生レンダリング経路である（レビューでも確認）。

### AC3: BPM を変えるとクリックの間隔が追随する — ✅

- クリック間隔は `project.bpm` から都度計算する。
- テスト `metronome_interval_follows_bpm`: SetBpm で 60 に
  変えると 0ms・1000ms にクリックがあり、500ms 地点には
  鳴らないことを確認。
