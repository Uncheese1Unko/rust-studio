## 設計

- 換算と形状はすべて `timeline.rs` の GUI 非依存の純粋関数にした
  （既存の `ViewScale` 設計に倣う）。
  - `wheel_delta_ms(x_lines, y_lines, width)`: 1ノッチ＝表示幅
    （`visible_ms`）の 1/10。符号規約は y+＝戻る、y−＝進む、x+＝進むで、
    x と y を合算するため Shift+ホイールはプラットフォームが
    x／y どちらの表現で渡しても効く。
  - `max_offset_ms` ＝ `max(0, project_end_ms − visible_ms)`。
    `scroll_by_clamped` が上限クランプ付きスクロールで、ホイール／
    パン／スクロールバーの入口にのみ適用し、`zoom_at` のアンカー
    保持には適用しない（イシューの実装方針どおり）。
  - `scrollbar_thumb`: つまみの x／幅を表示範囲と全体の割合から
    決める（最小幅 20px、全表示時はトラック全幅）。
    `scrollbar_drag_to` はその逆変換（クランプ付き）。
    `scrollbar_y(track_count)` ＝ ルーラー高＋トラック行数×行高で、
    最終トラック行の直下の帯に置く。帯のヘッダ列（x<120）は
    トラック追加領域のため、スクロールバーは x≥120 に描く
    （`scrollbar_grab` が判定。帯内でつまみの外を掴んだ場合は
    つまみ中心で掴む）。
- `main.rs`: `mouse_wheel` を書き換え（LineDelta の x 成分を捨てず、
  PixelDelta は両軸とも 50px＝1行の換算。Ctrl+ホイールのズームは
  従来どおり y で判定）。`handle_pointer` でスクロールバーの
  ドラッグを他の左ボタン処理より先に処理し、中ボタンパンは
  「掴んで動かす」方向（左へドラッグすると後の内容が見える）で
  px→ms 換算してクランプする。オフセットが変わったときだけ
  既存形式の `scroll offset: N` で記録する。

## 受け入れ条件ごとの結果

### AC1: ホイール1ノッチで表示幅の約 1/10 が移動し、移動量がズームに比例する — ✅

- 単体テスト `wheel_delta_is_proportional_to_visible_width` で
  ズーム1（表示幅 10,000ms）＝1,000ms、ズーム2＝500ms を固定。
- 実アプリ駆動（証拠 `evidence/issue-0085/`、終端 21,000ms の
  プロジェクト）で、ホイール1クリック＝2ノッチ（X11 では
  press+release の2イベント）＝2,000ms のオフセット変化を
  ログで確認した。

### AC2: 横ホイールと Shift+ホイールでも水平スクロールできる — ✅

- 駆動ログで横ホイール両方向（11,000→9,000、9,000→11,000）と
  Shift+ホイール（9,000→11,000）のオフセット変化を確認した。
- **測定で分かったこと**: 本環境の winit／X11 スタックでは、
  X11 ボタン6は LineDelta x=+1、ボタン7は x=−1 として届く
  （生デルタのデバッグ出力を一時的に入れて実測し、除去して
  再ビルドした）。駆動スクリプトの期待値をこの実測規約に
  合わせて再実行し、全チェック通過を確認した。

### AC3: タイムライン下端にスクロールバーが描かれ、つまみが表示範囲と全体の割合を表し、ズームやスクロールに追従する — ✅

- スクリーンショット `01-initial.png` で、オフセット 0 のときの
  つまみの画素（rgb (115,115,133)）と帯（rgb (33,33,41)）が
  形状計算と一致することを確認。`02-dragged-end.png` では
  つまみの右端が画面右端に一致する。
- つまみは毎フレーム `view_scale` から描き直すため、ズーム／
  スクロールに追従する。形状は単体テスト
  `scrollbar_thumb_reflects_offset_and_visible_ratio` でも固定。

### AC4: つまみをドラッグして任意の位置へ移動でき、終端より先へは進まない — ✅

- 駆動でつまみを 320px→530px へドラッグし、オフセットが
  ちょうど 5,250 になって `scrollbar drag end` が記録される
  ことを確認。右端までドラッグするとオフセットは上限
  11,000（＝21,000 − 10,000）で止まり、それ以上進まない。
- 単体テスト `scroll_by_clamped_stops_at_project_end` と
  `scrollbar_drag_to_round_trips_and_clamps` でも固定。

### AC5: 中ボタンドラッグでパンできる — ✅

- 駆動で中ボタンを 516px→600px へドラッグし、オフセットが
  11,000→10,000（−84px ＝ −1,000ms）に変わることをログで確認。

### AC6: 既存の操作が従来どおり動く — ✅

- `./scripts/verify.sh` 全通過（fmt / clippy / ワークスペース全
  372 テスト）。駆動で Ctrl+ホイールズーム（1.25→2.44、
  マウス位置アンカー）を確認し、別起動でクリップドラッグ
  （start_ms 1,000→2,000）の回帰確認も行った。スクロールバーの
  帯は最終トラック行の下の空き領域に置くため、トラック行上の
  クリップ操作（ドラッグ・トリム・ダブルクリック配置・
  フェード判定）とは重ならない。
