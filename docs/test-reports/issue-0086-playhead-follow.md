# 試験レポート: #86 DAW の再生ヘッドへの表示追従

対象 PBI: #86「DAW の再生ヘッドが画面外に出たらタイムライン表示が追従する」
実施日: 2026-11-24
実装コミット: `8777afa`（feat）、`dabcbd3`（レビュー指摘の修正）
ベース: `b3ab4b1`

動画側 #84（コミット `fb782d9`）の設計を流用し、DAW 固有の差分（ループ範囲の折り返しも巻き戻り検出で拾う、F キーはテキスト編集中は発動させない）を加えた。

## 実装内容

- `apps/daw/src/timeline.rs`: `ViewScale::visible_ms` と `ViewScale::follow_playhead(playhead_ms, wrapped)` を追加（純粋関数）。再生ヘッドが表示範囲内の間はオフセット不変、右端超過時のみページ単位で進める。巻き戻り時は「折り返し先を含むページの先頭」へ戻す（終端ラップでは再生ヘッドが 0 付近に戻るため結果として 0 になる。ループ折り返しではループ始端を含むページになる）。
- `apps/daw/src/main.rs`: `Model.follow_playhead`（既定オン）と `prev_f_down` を追加。F キーの押下エッジでオン／オフを切り替え、`follow: on/off` を標準出力に出す。リネーム／BPM 編集中は `prev_f_down` の同期のみ行い切り替えない（バグ #60 のパターン）。追従の適用は `advance_playhead_in_loop` の直後で、オフセットが変わったときだけホイールと同じ形式 `scroll offset: N` を出力する。
- F キーはサンプラーのノートキーでもあるため、切り替えと同時にノートオンが鳴る（イシュー指定どおり F キーを採用した結果の副作用として許容）。

## TDD の記録（red）

1. 最初の red: 単体テスト3件（`follow_playhead_pages_forward_past_right_edge`、`follow_playhead_keeps_offset_when_playhead_in_view_or_before`、`follow_playhead_resets_offset_on_wrap`）を先に書き、`follow_playhead` 未実装のため E0599（メソッドが無い）でコンパイル失敗を確認した。実装後に green。
2. レビュー指摘の修正時の red: `follow_playhead_resets_offset_on_wrap` にループ始端ケース（再生ヘッド 20,100 へ折り返し → オフセット 20,000 を期待）を追加し、旧実装（巻き戻り時は一律 0）に対して `left: 0, right: 20000` のアサーション失敗を確認した。ページ先頭へ戻す実装に直して green。

## 実アプリ駆動（GUI 証拠）

Xvfb（display :97）＋ lavapipe ソフトウェアレンダリングで実アプリを駆動した。**実ディスプレイ／実 GPU での見え方は未検証。**

駆動スクリプトは `evidence/issue-0086/drive.sh`、標準出力ログは `gui-stdout-a/b/c.txt`、スクリーンショットは `01-initial.png`〜`05-loop-wrapped.png`。

- 起動 A（プロジェクト終端 21,000ms）: 右端超過前はオフセット不変、超過時に `scroll offset: 10000` がちょうど1回だけ出力され、追従後も再生ヘッドの縦線が画面内に写る（ピクセル確認）。F キーで off → on → off の切り替えログを確認。オフの間は 20,000ms 超過と 21,000ms のラップでもオフセットが変わらない。
- 起動 B（終端 11,000ms）: ページ送り後に終端ラップで `scroll offset: 0` に戻る。
- 起動 C（終端 21,000ms）: ルーラー上のドラッグでループ範囲 12,000..15,000 を設定し、ループ折り返し後もオフセット行が出ず（折り返し先が同じページ内のため）、再生ヘッドの縦線が画面内に残ることを確認。
- 駆動上の注意: F キーはサンプラーのノートキーでもあり、長い音源（22秒）ではピッチシフト処理が `update()` を数秒ブロックし、後続の F 押下を取りこぼした。アプリの不具合ではなく駆動側の問題で、音源を1秒のトーンに替えて解消した（クリップ長 21,000ms はプロジェクト側で維持）。
