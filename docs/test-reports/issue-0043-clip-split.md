## 受け入れ条件ごとの結果

### AC1: GUI でクリップを選択し、再生ヘッド位置で分割するキーを押すと画面上で2つに分かれる — ✅

- S キーの押下エッジで、選択中トラックで再生ヘッドが内側
  （両端を除く）にあるクリップを `split_at_playhead` が
  SplitClip コマンド（#32）経由で分割する。対象が無い場合は
  ログだけの no-op。
- 実アプリ証拠（`evidence/issue-0043/`）: 6秒クリップを S で
  分割し、ダンプで 0..3562 / 3562..6000（右 offset_ms=3562）に
  分かれたこと、スクリーンショットでタイムラインに2本出ること
  を確認。対象なしケース（空プロジェクト）もログのみで状態
  不変を確認。

### AC2: 分割した右側クリップのプレビューが、分割前の続きの映像を表示する — ✅

- `media::source_time_ms` を「素材時刻 = offset_ms + クリップ内
  位置」に修正（従来は offset を落としていた）。プレビューの
  観測ログ・描画・切り抜き合成のフレーム選択はすべてこの関数
  経由。
- イシュー指定テスト `frame_at_uses_clip_offset` が、実物の
  SplitClip で作った右クリップについて素材時刻 500/1500・
  フレーム 5/15 を固定（旧計算では 0/1000 で落ちる）。
- 実アプリ証拠: 分割後の右クリップ区間で
  `preview: playhead=5417 source_time=5417 frame=54`（offset が
  効かなければ frame は 18 台）。フレーム画像の比較でも、
  分割直後の表示フレーム（番号・明るさが時刻に比例する素材）の
  明るさが素材の頭付近（3.3）と大きく異なり続き側（151.8）で
  あることを確認。スクリーンショット `02-after-split.png` は
  右クリップ区間（playhead=4642、frame=46）で撮り直した。

### AC3: MCP からも分割でき、ダンプで観測できる — ✅（既存の担保）

- #32 で追加済みの MCP テスト `split_clip_tool_applies_via_
  tools_call`（crates/studio-mcp/tests/mcp_tests.rs）が
  tools/call 経由の分割と右クリップの offset_ms を担保して
  おり、本変更でも MCP 23 件全通過に含まれる。本件での MCP
  側の変更はない（作業中に同名テストを重複追加しかけ、既存に
  気づいて取り下げた）。
