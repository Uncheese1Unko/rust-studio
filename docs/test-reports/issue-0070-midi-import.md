## 設計と実装判断（実装レベルの小判断を含む）

- **SMF パースは midly クレート**（0.5.3、純 Rust）を使う。
  VLQ・ランニングステータス・メタイベントの自前処理はバグの
  温床になるため。studio-core の依存に追加（Cargo.lock 更新）。
- **変換は純粋関数** `parse_midi`（`crates/studio-core/src/
  midi_import.rs`）: SMF バイト列 → `MidiImport`（bpm と
  トラック列）。適用 `import_midi` はコマンド列（SetBpm →
  AddTrack → AddClip → AddNote）に変換して履歴へ適用する。
  状態変更はコマンド層経由のみ（ADR-0004）。
- **原子性と Undo**: 適用は複製の上でコマンド列を最後まで
  適用してから `History::commit_replacement` で一度に差し替える
  （レビュー対応でこの方式に変更。旧方式の「事前検証＋実適用」
  では万一の実適用失敗時に部分適用が残り得た）。取り込み全体が
  Undo 1回で戻り、失敗時は状態も履歴も変わらない。
- **割り当ての細部**（イシュー方針の具体化として判断・記録）:
  - ノートの無い SMF トラック（コンダクター等）は DAW トラック
    を作らない。
  - クリップはノート列の範囲（最初のノート開始〜最後のノート
    終了）に置き、ノートはクリップ相対にする。クリップ名と
    トラック名は SMF のトラック名（無ければ `MIDI <番号>`）。
  - 同じ音の重なりは FIFO で対応付け。ベロシティ 0 のノート
    オンはオフ扱い。対応の無いノートオフは無視。ノートオフの
    無いノートはトラック終端で閉じる。変換後に長さ 0 以下に
    なるノートは捨てる（モデルの不変条件: 長さは正）。
  - ドラム ch.10 も通常チャンネルと同じ統合（イシュー記載）。
- **テンポ**: テンポマップは全トラックから集め、点の無い区間は
  標準 500000us（120 BPM）。プロジェクト bpm には先頭テンポを
  入れるが、SetBpm の範囲（20–300）外なら入れない（変換自体は
  テンポマップで正確に行う）。SMPTE division はエラー。
  ノートが1つも無いファイルもエラー（`NoNotes`）として、
  何も取り込めないことを黙って成功にしない。
- **入口は3つ**: GUI のドロップ（.mid/.midi をオーディオ配置と
  分岐。取り込みは履歴に積まれ Undo 可能、開いているピアノ
  ロールは閉じる）、検証用 CLI `daw --import-midi <project.json>
  <file.mid>`（--export-wav の前例）、MCP ツール `import_midi`
  （{path}、get_project 等と同じ特殊ツール扱い）。
