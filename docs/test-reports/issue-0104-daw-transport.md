# 試験レポート: #104 DAW で再生／一時停止・シーク・先頭／末尾ジャンプができる

対象 PBI: #104「DAW で再生／一時停止・シーク・先頭／末尾ジャンプができる」（EPIC #103）
実施日: 2026-11-27
ベース: `b1e366e`

根本原因は、GUI に再生状態が存在せず `update()` が毎フレーム無条件に再生ヘッドを進めていたこと。再生状態を GUI の操作状態として持ち、前進をトランスポート経由に変え、ルーラークリックとキー／ボタンからシークできるようにした。

## 実装内容

- `apps/daw/src/timeline.rs`: 純粋関数として追加。
  - `PlayState`（`Playing` / `Paused`、`toggle()`、`is_playing()`）。
  - `transport_advance(state, current_ms, dt_ms, end_ms, loop_range, loop_on)`: 停止中は現在位置をそのまま返し、再生中は既存の `advance_playhead_in_loop` に委ねる（終端ラップとループ折り返しの既存挙動を維持）。
  - `seek_clamp(ms, end_ms)`: `[0, 終端]` にクランプ。終端 0（空プロジェクト）なら常に 0。
- `apps/daw/src/main.rs`:
  - Model に `play_state`（初期値 `Paused` ＝起動時は停止）とスペース／Home／End の押下エッジ追跡を持つ。キー処理はテキスト編集中でないときだけ行い、編集中は prev を同期だけする（バグ #60 のパターン。対象セッションはリネーム、BPM 入力、音色改名）。
  - `update()` の再生ヘッド前進を `transport_advance` 経由にした。再生追従（#86）の処理は従来どおり毎フレーム行う。
  - シークは `seek_to` ヘルパーに集約: クランプして `playhead_ms` を設定し、追従が有効なら `ViewScale::follow_playhead`（巻き戻り判定は「新位置 < 旧位置」）で表示を合わせ、`seek: <ms>` を stdout に出す。トグル時は `transport: playing` / `transport: paused` を出す（観測経路、ADR-0005）。
  - トランスポートボタンはトランスポートパネル1行目: 再生／一時停止（x=230, w=104）、先頭 START（x=342, w=72）、末尾 END（x=422, w=72）、いずれも y=パネル上端+8、高さ 28（2行目チップが +38 から始まるため、当初案の 32 では 2px 重なることをスクリーンショット確認で見つけて 28 にした）。進行バーとレベルメーターは x=506, w=184 へ移動。再生中はボタンがテーマの ACCENT 面＋ PAUSE ラベルになる（メトロノーム ON と同じ「現在状態はピンク」の約束、ADR-0012）。
  - ルーラー: 既存のループ範囲ドラッグ確定処理で、`loop_range_from_drag` が None（50ms 未満の移動＝クリック）のときアンカー位置へ `seek_to` する。ドラッグ（50ms 以上）＝ループ範囲指定（#40）の既存挙動はそのまま。

## 状態ダンプに関する判断

再生状態と再生ヘッド位置はプロジェクトの保存対象ではない（表示・操作の状態）。状態ダンプ（プロジェクトダンプ）には含めない。根拠: architecture.md の原則「ダンプは画面で観測できるものと一致する」は、ダンプがプロジェクト状態を映すことを求めるもので、GUI 操作状態まで含めることは求めていない。先例も同じ扱いである（メトロノーム #36、ループ範囲 #40、再生追従 #86 はいずれもプロジェクトに保存せずダンプにも含めない）。トランスポートの観測は、画面（ボタンの見た目と時刻表示）と stdout ログ（`transport:` / `seek:` / `scroll offset:`）で行う。

## 「停止中に音が出ない」ことの根拠

GUI のタイムライン再生に音声デバイス出力は無い（デバイス出力を持つ `Player` は `--engine-demo` 経路のみで GUI と未接続）。再生ヘッド連動の音の現れは、レベルメーター用の `render_mix`（再生位置が 50ms 以上動いたときだけ再計算）とクリップの発音中表示であり、どちらも再生ヘッドが止まれば進まない。駆動では、停止中に画面全体（レベルメーターと時刻表示を含む）が2秒間不変であることをスクリーンショットの完全一致で示した。

## 実アプリ駆動（GUI 証拠）

Xvfb（display :99）＋ lavapipe ソフトウェアレンダリングで実アプリを駆動した。**実ディスプレイ／実 GPU での見え方は未検証。**

駆動スクリプトは `evidence/issue-0104/drive.sh`、標準出力ログは `evidence/issue-0104/gui-stdout.txt`、スクリーンショットは同ディレクトリの `01`〜`11`。デモプロジェクト（1トラック、終端 4,500ms）で全18チェック PASS:

- 起動直後: 2.5秒待っても画面が完全一致のまま（停止状態でヘッドが動かない）。入力前に `transport:` ログは無い。
- スペース長押し → `transport: playing` が出てヘッドが進む（画面が変化）。再度押す → `transport: paused` が出て、その位置で画面全体（レベルメーター・時刻表示を含む）が2秒間完全一致のまま止まる。
- ルーラークリック（x=378）→ `seek: 3071` が出てヘッドがその位置へ移動。
- ルーラードラッグ（x=252→420）→ `loop range: 1571..3571` が出て、従来どおりループ範囲が作れる（クリック＝シークと両立）。
- Home → `seek: 0`、End → `seek: 4500`。
- ボタン: END → `seek: 4500`、START → `seek: 0`、PLAY → `transport: playing`、PAUSE → `transport: paused`。再生中のボタンはピンク＋ PAUSE 表示（`09-playing-by-button.png`）。
- リネーム編集中（トラックヘッダーのダブルクリックで開始）にスペースを押しても `transport:` ログは増えない。
- Ctrl+ホイールでズームして表示範囲を狭めた状態で、停止中に End → `seek: 4500` と同時に `scroll offset:` が変わり、追従表示がシーク先へ追いつく。
- 駆動上の注意: アプリは毎フレームポーリングのため、xdotool の瞬時 `click`（押下と解放が1フレーム内に収まる）は取りこぼす。実利用のクリックは1フレームより長いためアプリ側の問題ではなく、駆動側で押下を 0.35 秒保持する方式に替えて解消した。
