## 実装の概要

- `apps/daw/src/audio.rs`: WAV デコード（hound、ビット深度で正規化）、
  プル型の `render_mix`（配置・クリップゲイン・線形補間の
  リサンプリング）、再生位置の状態機械 `Player`。
- コンソールデモ（`--engine-demo`）でミックスダウン WAV と
  秒ごとの RMS、Player の遷移を出す。
- 時刻は f64 で扱う（整数ミリ秒の丸めで波形が階段状になり音程が
  壊れる問題をテストで検出して直した）。

## 受け入れ条件ごとの結果

### AC1: 複数クリップが開始位置どおりに重なって再生される — ✅（レンダリングとして。聴取は未検証）

- `render_places_clips_at_their_positions`: 区間ごとに 440Hz のみ／
  両方／880Hz のみ／無音を Goertzel 解析で検証。重なりの合計も
  比率 2.0±0.1 で固定。
- デモのミックスダウン（証拠: [evidence/issue-0013/](evidence/issue-0013/)）:
  配置どおりの RMS 推移（0.1414 / 0.3162 / 0.2828）。
- 確認方法に書かれた「実アプリでの聴取」は、音声出力デバイスが
  ないため未実施。この差異は本レポートと Issue のクローズ
  コメントに明記し、聴取は needs-human として残す。

### AC2: ゲイン（SetClipGain）が再生音量に反映される — ✅

- `render_applies_clip_gain`: gain 1.0 と 0.5 の RMS 比 0.5±0.05。

## TDD の記録

- デコード・配置・ゲイン・重なり・Player 遷移のテストを先に書き、
  落ちることを確認してから実装した。途中で2件の実バグを検出:
  (1) 整数ミリ秒への丸めで波形が階段状になる → f64 時刻に修正。
  (2) hound の i32 読みを i32 最大値で割って振幅が化ける
  → ビット深度（2^(bits-1)）での正規化に修正し、振幅の assert を強化。
- レビュー対応では、リサンプリング（22050Hz→44100Hz で音程保持）、
  24bit デコードの正規化、Player の seek 上限クランプのテストを
  追加した（実装は既に正しく、仕様の固定が目的）。
