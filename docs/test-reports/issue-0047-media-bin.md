## 受け入れ条件ごとの結果

### AC1: メディアビンのパネルに、メディアディレクトリ内の対応ファイル（動画・画像）が名前付きで一覧される — ✅

- 列挙は `media::list_media`（純粋関数）: ファイルのみ、拡張子
  mp4/mov → 動画、png/jpg → 画像（大文字小文字を区別しない）、
  名前順。音声（wav）やフレーム置き場のディレクトリは含めない。
- 実アプリ証拠: パネル（要素識別子 `media-bin`、ヘッダー
  「MEDIA BIN (R: RELOAD)」）に bg.mp4 / interview.mp4 /
  opening.mp4 が並び、bgm.wav が無いことをスクリーンショットと
  stdout の `media bin:` 行で確認（`evidence/issue-0047/01-bin.png`）。

### AC2: ビンで素材をダブルクリックすると、選択中トラックの再生ヘッド位置にクリップとして配置される — ✅

- 配置は AddClip コマンド経由のみ。長さは動画なら ffprobe の
  実尺（解釈できなければ既定の新規クリップ長 2,000ms）、画像は
  2,000ms。
- 実アプリ証拠: 実尺3秒の extra.mp4 をダブルクリックし、V1 の
  再生ヘッド位置（1214ms）に duration 3000ms で配置されたことを
  状態ダンプ（`project after edit:`）とスクリーンショット
  （V1 行に extra のクリップ面が出現）で確認。

### AC3: 素材が増減したら、再起動なしで一覧に反映される（再読み込み操作でよい） — ✅

- 再読み込みは R キー（押下エッジ）とパネルヘッダーのクリック。
- 実アプリ証拠: 起動後に extra.mp4 を追加し、R キーで一覧に
  加わったことを `media bin:` 行とスクリーンショットで確認。

## GUI ドライブの注記（正直な記録）

- 当初、配置の証拠が取れず原因究明に時間を要した。原因は2つ
  ともドライブ側: (1) `xdotool click` の短い押下（10ms 程度）は、
  フレーム展開中など更新間隔が長い場面でポーリング型の入力に
  取りこぼされる。保持クリック（mousedown→0.2秒→mouseup）に
  変えて解決した。(2) 配置直後のフレーム展開が終わる前に撮影・
  終了していた（レビュー round 1 の指摘）。ダンプ行を待つよう
  直して証拠を取り直した。
- ビンのパネル位置はトラック数で決まる（パレットパネルの下）。
  ドライブはフェーズごとにトラック数を数えて行位置を計算する。
