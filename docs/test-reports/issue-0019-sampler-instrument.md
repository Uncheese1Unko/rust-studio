# 試験レポート： Issue #19 サンプラー楽器（取り込んだ音を音程で演奏する）

- 日付: 2026-11-21
- 実行者: エージェント（デリバリーループ、二周目）
- 対象コミット: `c34eb1a`（実装）
- CI: スタック push 後に記録する
- 環境: Yoko の VM（Linux, ヘッドレス）。音声出力デバイスはなく、
  **聴取による確認は実機未検証**。検証はレンダリング結果の解析と
  GUI の発音状態（鍵盤表示・操作ログ）で行った。

## 実装の概要

- `apps/daw/src/sampler.rs`: ノートオン／オフ → ボイス → ミックスの
  状態機械。ピッチ処理は #18 の `pitch_shift`（ADR-0009）を共用し、
  自前のピッチ処理は持たない。
- キー配置はピアノ式（a=ルート、w/s/e/d…で半音ずつ、k=+12）。
  素材は再生ヘッド位置の音声クリップ、無ければ配置用素材。
- GUI: 鍵盤ストリップで発音中のノートを点灯表示し、ノートオン／
  オフと発音中一覧を操作ログ（標準出力）に出す。演奏状態は
  一時的なもので、プロジェクト状態には入れない（Player と同じ扱い）。

## 受け入れ条件ごとの結果

### AC1: 取り込んだ音を選び、音程を指定して鳴らせる — ✅

- 単体テスト: 220Hz の素材に +12 で 440Hz が鳴り 220Hz が消える
  ことを周波数解析で検証。
- 実アプリ駆動（証拠: [evidence/issue-0019/](evidence/issue-0019/)）:
  キー操作で素材が確定し（`sampler source:` ログ）、ノートオンが
  記録された。

### AC2: 音程を変えても元の音の性質（フォルマント）が保たれる — ✅（測定）

- 証拠: [evidence/issue-0019/analysis.txt](evidence/issue-0019/analysis.txt)。
  単純リサンプリングでは包絡ピークが 730→1080Hz へ移動するのに対し、
  サンプラー +7 ではピークが元の 720Hz 付近に留まり、高域の
  持ち上がりもない。なお +7 のピークは 720 と 900Hz が拮抗する
  （0.0473 / 0.0483）弱めの証拠であり、その旨も分析に明記した。
- 聴取確認は実機未検証（デバイスなし）。

### AC3: 演奏（ノートオン）がコマンド／状態として観測できる — ✅（操作ログ）

- 確認方法は「状態ダンプまたは操作ログ」。操作ログに
  `note on: +0, active: [0]` → `[0, 4]` → `[0, 4, 7]` と
  ノートオフの遷移まで記録され、GUI の鍵盤表示とラベルにも
  同じ状態が出る。演奏状態をプロジェクトのコマンドにしなかった
  判断は Player の前例と整合する（レビュアーも同意）。

### AC4: 同時発音（和音）ができる — ✅

- 単体テスト: 3音（220 / 277.18 / 329.63Hz）の同時検出。
- 実アプリ: A+D+G の同時押しで active [0, 4, 7] と鍵盤の点灯を
  スクリーンショットで確認。
- オフライン証拠 chord.wav の3基本音（120 / 151.2 / 179.6Hz）を
  解析で確認（レビュアーも独自解析で再現）。
