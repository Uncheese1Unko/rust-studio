# Bug Handling — バグは直し切る

- バグは、severity を問わず、見つけた時点で最後まで直す。再現 → 根本原因 →
  再現する落ちるテスト → 修正 → ゲート → レビュー → push → CI → 記録。
- 現在の PBI の範囲内のバグはその PBI の中で直す。範囲外ならバグ PBI を作り、
  今の作業を再開する前に直す。バグ PBI は記録であってバックログではない。
- バグに `blocked` は付けない。3回試して駄目なら、アプローチを変える
  （最後の緑の状態に戻る、設計を疑う、小さく割る）。止まらない。
- ただし権限は広がらない：force-push、他人の作ったものの削除、サインアップ、
  支払い、秘密情報の扱い、ゲートの弱体化はしない。別の方法を探す。
- 設計判断が絡むバグは、判断そのものを勝手に決めない。`needs-decision` で
  人間に渡す（delivery-loop §3）。
