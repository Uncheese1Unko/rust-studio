# Documentation — 文書と ADR

- `docs/` の各ディレクトリには `index.md` を置き、文書への入口を1つに保つ。
  文書を足したら `docs/log.md` に1行残す。
- 判断（アーキテクチャ・技術・横断ルール）は `docs/adr/` に ADR として残す。
  テンプレートは `docs/adr/template.md`。番号は連番、タイトルは判断内容。
- **ADR はその判断をした変更と同じコミットで足す**。採用済み ADR は編集しない。
  覆すときは新しい ADR を作り、旧 ADR のステータスを superseded にしてリンクする。
- スタックや構造の変更を提案する前に、既存の ADR を読む。決まっていることを再決定しない。
- 判断には決定者を書く（人間／エージェント）。エージェントが決めた実装レベルの
  小判断も ADR に残し、最終報告で明示する。設計判断はエージェントが決めない
  （`needs-decision` で人間に渡す）。
