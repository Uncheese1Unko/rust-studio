# Delivery Loop — EPIC の sub-issue を1件ずつ消化する

EPIC、マイルストーン、「次のイシュー」の実装を頼まれたときに適用する。
1つのループが、人間を挟まずに EPIC の最初の open な sub-issue から最後まで運ぶのが目標。
ただし**設計判断だけは例外**：判断に当たったら止まって人間に渡す（§3）。

## 1. 1イテレーション = 1 PBI（着手から close まで）

1. **真実の確認**：`git fetch origin`。`main` が遅れていないこと、CI が緑なこと。
   赤い `main` は何より先に直す。
2. **選ぶ**：EPIC の一覧の順に、open で blocked by が全部閉じている最初の1件を取る。
   open なブロッカーを飛ばして先に進まない。
3. **読む**：イシュー本文が仕様。リンクされた ADR とアーキテクチャ文書を読む。
   ADR が答えていることを再決定しない。
4. **ベースライン**：変更前に `cargo test` を回し、結果を控える。
5. **TDD で実装**（`.claude/rules/tdd.md`）。受け入れ条件の失敗するテストから。
   振る舞いごとに：テストを書く → 期待した理由で落ちるのを見る → 最小のコードで
   通す → リファクタ。red はその場で試験レポートの「TDD の記録」に残す。
6. **検証**：`cargo test`（および用意された verify コマンド）が 0 で終わること。
   受け入れ条件を、イシューに書かれた確認方法で1つずつ確かめる。
   画面で観測できる条件は実アプリで確認し、証拠（スクリーンショット）を残す。
   computer use テスト用に、API の状態ダンプでも同じ状態が観測できることを確かめる。
7. **独立コードレビュー**（`.claude/rules/code-review.md`）。push の前に、新規の
   `code-reviewer` サブエージェントにイシュー番号と diff 範囲だけを渡す。
   指摘は自分で1つずつ確かめ、本物はテスト先行で直し、誤りは根拠付きで退ける。
   APPROVE が出るまで新しいレビュアーで回す。コード変更のない PBI のみ省略可。
8. **判断の記録**：途中で生じた判断は同じコミットで ADR にする。設計判断は
   自分で決めず §3 に従う。
9. **コミット＆ push**：パスを明示して stage、`git diff --check`、メッセージに
   `Refs #N` を含める。force-push はしない。
10. **CI を最後まで見る**：緑なら続行。赤なら今すぐ前に直す。次の PBI を始めない。
11. **試験レポート**：`docs/test-reports/issue-NNNN-<summary>.md`（証拠は
    `docs/test-reports/evidence/`）。受け入れ条件ごとの結果と証拠、ゲート出力、
    TDD の記録、レビュー結果を書く。push し、その CI も緑であること。
12. **close**：完了の定義の全項目を満たしたときだけ。コメントに commit SHA、
    CI の URL、試験レポートへのリンクを書いて閉じ、EPIC の一覧でチェックする。

## 2. ループが決してしないこと

- 未達の受け入れ条件、飛ばしたゲート、赤い CI、証拠なしでイシューを閉じる
- 失敗するテストより先に本番コードを書く／後からテストを足して済ませる
- 独立レビューを通っていないコードを push する／自分の要約や推論をレビュアーに渡す
- 終わらせるためにゲートを弱める、テストを skip する
- 無関係な改善をコミットに混ぜる（隣の改善は別 PBI。隣の**バグ**は
  `.claude/rules/bug-handling.md` に従い、その場で直す）
- 既知のバグを開いたままにする、severity で先送りする

## 3. 止まる条件（人間に渡す）

- **設計判断**：選択肢が複数あり、ADR とルールで決まらない点。実装を止め、
  `needs-decision` ラベルを付け、選択肢・推奨・理由を提示して人間に渡す。
  決まったら ADR に記録してから再開する。
- **人間にしかできないこと**：アカウント、支払い、秘密情報、実機確認など。
  `needs-human` ラベルを付け、理由を書いて、その PBI を飛ばして続行する。
- 実装レベルの小判断（命名の細部など）は止まらずに決めてよいが、ADR に記録し、
  最終報告に「AI が決めた判断」として挙げる。

## 4. 終了

ループは EPIC の sub-issue が全部閉じたときに終わる。バグ、レビュー差し戻し、
赤い CI は停止理由にならない。

最終報告に挙げるもの：閉じたイシュー（SHA 付き）、書いた試験レポート、
見つけて直したバグ（バグ PBI 付き）、追加・supersede した ADR（AI が決めた判断を
明示）、`needs-decision` / `needs-human` で人間に渡したものとその理由。
