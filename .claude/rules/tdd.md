# TDD — 実装は常にテスト駆動

- 実装は常に TDD。Red → green → refactor、1つの振る舞いずつ。
  落ちるテストが要求していない本番コードは書かない。落ちるのを見ていない
  テストは信用しない。バグ修正は、再現する落ちるテストから始める。
- 外側から攻める：受け入れ条件に対するテスト（コアのコマンド層なら統合テスト、
  画面で観測できる条件なら E2E／computer use のシナリオ）が最初。
- **red はその場で記録する**。試験レポートの「TDD の記録」に、テスト名と
  落ちた理由を残す。記録がなければ TDD とは認めない。
- テストはコードと同じコミットに入れる。
